# Documentation

Keep each kind of information in one place:

- `rewrite-context.md` contains the rewrite's goals and guiding principles.
- `rewrite-log/` records chronological milestones, including failed approaches and lessons.
- `decisions/` explains architectural decisions that should remain understandable later.
- `systems/` describes how implemented systems currently work.

When finishing meaningful work, add a rewrite-log entry and link its relevant commits or test evidence. Add a decision record only when a choice has lasting architectural consequences. Update a system document when the implemented behavior changes.
